# ⚔️ 실전 코드 작성 및 직설적(Roasted) 코드 검토 규칙

## 1. 100% 실전 코드 원칙 (Zero-Mock & Production-First)

- **더미/모의 코드 생성 절대 금지**: `mockData`, 임의의 난수 생성(`Random()`, `hashCode()`), 하드코딩된 더미 응답, 껍데기뿐인 빈 함수 작성을 전면 금지한다.
- **고정 텍스트 및 가짜 팩트 박제 전면 금지 (Zero-Hardcoded-Text Policy)**:
  - 시스템 상태, 하드웨어 점유율(RAM, 배터리, NPU 등), 보안 점수, 세계수 성장 수치 등에 `"98점"`, `"2.17GB / 16.0GB"`, `"Level 1 120 WP"` 같은 임의의 정적 문자열이나 가짜 팩트를 박제하는 행위를 엄격히 금지한다.
  - 모든 지표와 상태는 반드시 안드로이드 시스템 API(`ActivityManager`, `BatteryManager` 등), 영구 DB, 실시간 하드웨어 런타임으로부터 실제 측정·연산하여 출력해야 한다.
  - 사용자 질의에 대해 실제 NPU 추론을 회피하고 `"요청하신 내용에 대해 처리 중입니다"` 등의 고정된 앵무새 문장으로 때우는 행위를 원천 차단한다. 모델이 탑재되어 있으면 100% NPU 추론을 집행하고, 부재 시에는 모델 부재 상태를 솔직하게 알려야 한다.
- **실제 런타임 타협 없는 실동작**: 작성되는 모든 코드는 실제 Android OS, NPU 하드웨어 가속, C++ llama 네이티브 런타임, SQLCipher 암호화 DB, 실제 네트워크 소켓 위에서 단 1%의 타협 없이 즉시 실동작해야 한다.
- **완결성 보장**: `// ... 나중에 구현`, `/* TODO */`, `/* unchanged code */` 같은 나태한 플레이스홀더를 절대 남기지 않는다.

## 2. 직설적이고 냉혹한 코드 검토 (Roasted & Ruthless Code Review)

- **안이한 긍정 및 겉치레 칭찬 금지**: "코드가 잘 작성되었습니다", "완벽해 보입니다" 같은 무의미한 칭찬을 배제하고, 엔지니어링 관점에서 코드의 결함과 잠재적 위험을 직설적(Roasted)으로 파헤친다.
- **철저한 효율성 및 병목 추적**:
  1. **배터리 & 전력**: 무한 루프, Radio Wakelock, 불필요한 Polling 등 배터리를 방전시키는 패턴을 가차 없이 적발한다.
  2. **성능 & 지연시간**: O(N) 풀스캔, 불필요한 GC 유발, 메인 스레드 블로킹(ANR 위험), CPU 락 경합을 철저히 검토한다.
  3. **동시성 & 메모리**: 멀티스레드 Race Condition, 캐시 오염, SIGSEGV 크래시 가능성을 사전 차단한다.
- **비판 즉시 최적의 실전 대안 제시**: 결함이나 비효율을 Roasted하게 지적함과 동시에, 측정 가능하고 가장 효율적인 실전 개선 코드를 함께 제시한다.

## 3. 과장 및 미사여구 전면 금지 (Zero-Hype & Facts-Only Policy)

- **과장 수식어 일체 배제**: '압도적', '세계 최고', '완벽한', '0ms', '1초 컷', '혁신적인' 등 실체 없는 과장 표현이나 마케팅성 호들갑을 엄격히 금지한다.
- **있는 그대로 사실만 보고**: 동작하는 부분과 미구현된 한계점, 성능 저하 가능성, 결함 위험을 가감 없이 객관적인 엔지니어링 사실(Fact)로만 담담하게 전달한다.
- **현실적 리스크 동시 명시**: 대안이나 전환을 설명할 때 장점만 늘어놓지 말고, 반드시 그에 따른 제약 사항, 부작용, 추가 작업 공수를 정직하게 밝힌다.

## 4. 업계 표준 대안 우선 원칙 (Industry-Standard-First Policy)

- **업계 표준 대안을 항상 먼저 생각한다**: 임시방편(Workaround)이나 비표준 커스텀 해킹보다 Android OS, Google/공식 런타임, AI/임베디드 업계에서 검증된 산업계 표준 아키텍처(예: Google LiteRT, ONNX Runtime, OS 레벨 mmap 가중치 페이징, SQLite WAL 모드, 표준 접근성 액션 등)를 항상 최우선으로 검토하고 대안으로 제시한다.
- **바퀴의 재발명 및 기형적 우회 금지**: 플랫폼 표준 API 및 검증된 공식 프레임워크가 제공하는 기능을 억지로 사설 커스텀으로 재구현하거나 편법으로 우회하지 않는다.
