# 🤖 Yggdrasil Project Agent Guidelines (`AGENTS.md`)

---

## ⚔️ 1. 100% 실전 실동작 코드 원칙 (Zero-Mock Policy)
- **더미/모의 코드 생성 절대 금지**: `mockData`, 임의의 가짜 난수(`Random()`, `hashCode()`), 하드코딩된 더미 응답, 껍데기뿐인 가짜 함수 작성을 전면 금지한다.
- **실제 런타임 타협 없는 실동작**: 작성되는 모든 코드는 실제 Android OS, NPU 하드웨어 가속, C++ llama 네이티브 런타임, SQLCipher 암호화 DB, 실제 네트워크 소켓 위에서 단 1%의 타협 없이 즉시 실동작해야 한다.
- **완결성 보장**: `// ... 나중에 구현`, `/* TODO */`, `/* unchanged code */` 같은 나태한 플레이스홀더를 절대 남기지 않는다.

---

## 🔥 2. 직설적이고 냉혹한 코드 검토 (Roasted & Ruthless Code Review)
- **안이한 긍정 및 겉치레 칭찬 배제**: "코드가 잘 작성되었습니다", "완벽해 보입니다" 같은 립서비스를 일체 배제하고, 엔지니어링 관점에서 코드의 숨은 결함과 잠재적 위험을 직설적(Roasted)으로 파헤친다.
- **철저한 효율성 및 병목 추적**:
  1. **배터리 & 전력**: 무한 루프, Radio Wakelock, 불필요한 Polling 등 배터리를 방전시키는 패턴을 가차 없이 적발한다.
  2. **성능 & 지연시간**: O(N) 풀스캔, 불필요한 GC 유발, 메인 스레드 블로킹(ANR 위험), CPU 락 경합을 철저히 검토한다.
  3. **동시성 & 메모리**: 멀티스레드 Race Condition, 캐시 오염, SIGSEGV 크래시 가능성을 사전 차단한다.
- **비판 즉시 최적의 실전 대안 제시**: 결함이나 비효율을 Roasted하게 지적함과 동시에, 가장 효율적이고 실전 적용 가능한 최적화 코드를 함께 제시한다.

---

## 🛡️ 3. 시스템 무결성 검증 및 테스트 실행 정책
- **상시 전수 검사 금지**: 사소한 편집이나 일반 질의응답 시마다 `verify_total_integrity.py` 등의 무결성 검사 스크립트를 습관적으로 자동 실행하지 않는다.
- **검사 실행 허용 조건**:
  1. **대규모 업데이트 완료 시**: 핵심 시스템 코어, 런타임, DB 아키텍처 등 광범위한 변경이 일단락되었을 때.
  2. **주기적 마일스톤 점검 시**: 특정 Phase나 Milestone 전체가 완결되는 시점.
  3. **사용자의 명시적 요청 시**: 사용자가 직접 검사/테스트를 요청했을 때.
  4. **에이전트의 자체 판단 시**: 결합도나 런타임 무결성에 심각한 영향이 우려되어 반드시 검증이 필요하다고 판단될 때.
- **작업 행동 원칙**: 단순 문서 업데이트, 단일 파일 수정, 질의응답 시에는 검사를 생략하고 즉시 핵심 작업에 집중한다.
