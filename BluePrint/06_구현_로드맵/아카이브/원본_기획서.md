핵심 결정 (권장)

모바일 기본 플랫폼: Android 네이티브 → Kotlin (주 언어).
이유: Android는 시스템 권한·Keystore·백그라운드 제어·IOT 네트워크 접근 등에서 가장 세밀한 제어가 가능. Kotlin은 현대적이고 코루틴·타입 안전성 좋음.

보조언어(선택): Java(라이브러리 호환시), Kotlin Multiplatform(Java/Kotlin 공유 로직 필요 시), Flutter/React Native는 UI 빠르게 만들 때 고려하되, 네이티브 기능이 많으니 권장하지 않음.

백엔드(옵션·프라이버시 우선):

프라이버시-최우선(권장): 서버 최소화 / self-hosted optional — 사용자가 선택적 동기화만 허용. 서버는 ciphertext(암호화된 blob)만 저장.

언어: Go 또는 Rust 추천(경량·성능·보안). 대안: Kotlin (Spring Boot / Ktor) — 팀이 Kotlin에 익숙하면.

웹 대시보드 / 관리자 UI: React + TypeScript (Next.js) — 개발 편의상. 하지만 백엔드 불필요하면 생략 가능.

핵심 라이브러리: Jetpack Compose, Hilt, Room+SQLCipher, Retrofit+OkHttp, TFLite, libsodium/Tink, WorkManager

보안: Android Keystore/StrongBox, Ed25519 서명, AES-256-GCM, client-side encryption for sync

MVP 우선순위: 로컬 암호화, 권한 UI, 감사 로그, 학습 차단 → 이후 자동화·IOT·결제 기능 순차 확장

핵심 전제 (요약)

등급은 L0(가장 제한적) → L10(완전 자율·전권) 으로 증가.

상위 등급일수록 더 넓은 데이터 접근·자동화·외부 행위 가능.

L3 이상부터는 다중 인증·신뢰인 개입·주기적 재검토 등 사람 개입이 필수.

모든 권한 발급/회수/사용은 불변 서명 로그로 기록.

**학습(모델 업데이트)**은 별개 통제: 사용자 레벨에서 완전 차단(차단 모드)·부분 허용·항목별 허용 가능.

등급 총람 (한눈 요약)

L0 관찰자(Observe-only) — UI·알림 표시만. 읽기 불가 민감 데이터 없음.

L1 제한적 읽기(Read-minimal) — 제목/제스처/알림 메타만 읽음. 권장 기본.

L2 확대된 읽기(Read-extended) — 본문 일부·최근 위치(비실시간) 접근. 추천만.

L3 반자동(Assist-Automate) — IOT 제어(비치명적), 캘린더 쓰기, 규칙 기반 자동화(승인 필요).

L4 민감처리(Sensitive-Operate) — 파일 전송·첨부 이메일·비금융 결제 제안(자동화 제한).

L5 금융·거래(Transactional) — 결제 호출, 예약·구매 대행(흔한 제한: 상한선).

L6 사람대인 통신(Representative) — 외부인과 대화·협상 대행(사전 템플릿 필수).

L7 권한 위임(Proxy-Delegate) — 특정 업무의 전권 대행(계약·서명 불가 unless H/W 서명).

L8 조직적 행동(Organizational) — 회사·팀 계정 관리·조정, 타인 데이터 연동(엄격 감사).

L9 법적/공적 행동(Legal-Public) — 법적 문서 제출·수사 대응 보조(법률 검토 필요).

L10 전권 대행(Full Autonomy) — 사용자가 가능한 모든 행위의 자동 실행(최고 위험), 다중 신뢰인·하드웨어 키·법적 동의 필수.

이제 각 등급을 아주 자세히 쪼갠다 — 권한 항목, 자동화 허용, 승인 흐름, 스코프(범위), 예시, 롤백/실패 처리까지.

L0 — 관찰자 (Observe-only)

설명: 설치 직후 기본 등급. UI·시스템 알림만 표시. 어떤 민감 데이터도 읽지 않음.

허용 권한: 푸시 알림 표시, 로컬 UI 카드, 사용자의 직접 입력 텍스트 처리(명시적 입력만).

자동 수행: 전혀 없음. 제안·권장만 가능.

승인 흐름: 기본값. 사용자 별도 승인 불필요.

스코프 예시: “오늘 일정 있음” 알림 카드 표시(본문 불수집).

감사/로그: 설치/활성화 시 기록.

롤백: 즉시 가능(등급 변경 시 로그).

L1 — 제한적 읽기 (Read-minimal)

설명: 최소한의 읽기 권한 — 제목·메타데이터·연락처 이름 등.

허용 권한: 캘린더 제목, 알림 메타(발신자만), 연락처(이름·직업 태그), 노트 제목.

자동 수행: 추천·알림만. (사용자 승인 필요)

승인 흐름: 사용자 단독 승인(토글 방식).

스코프 제어: 시간(예: 30일), 장소(예: 집/회사) 레벨로 제한 가능.

예시: 캘린더 제목에 따라 “회의 있음” 카드 제공.

감사: 읽기 시점·대상 기록(메타만).

L2 — 확대된 읽기 (Read-extended)

설명: 문서 본문 일부, 이메일 제목+핵심 문장, 최근 위치 기록(실시간 아님) 등을 읽어 추천 가능.

허용 권한: 이메일 본문 요약(핵심 3문장), 구글 드라이브 파일 제목+요약(사용자 승인), 최근 24시간 위치 히스토리(비실시간).

자동 수행: 제안 후 사용자 단추 클릭으로 실행(“전송” 등은 직접 승인 필요).

승인 흐름: 사용자 인증(생체 또는 PIN) 권장.

스코프 제어: 필드 수준(예: 이메일에서 ‘비밀번호’ 문자열은 마스킹).

예시: “예약 확인 이메일 있습니다. 요약 생성할까요?”

감사: 원본 출처(파일ID·메일ID) 로그.

L3 — 반자동 (Assist-Automate)

설명: 규칙 기반 자동화와 로컬 IOT 제어가 가능. 민감하지 않은 장치·조작 자동화 허용.

허용 권한: 백그라운드 위치(제한적), 스마트라이트·로봇청소기 제어, 캘린더 쓰기, 미리 승인한 규칙 자동 실행.

자동 수행: 사전 승인된 시나리오(외출모드: 조명 끄기 등)를 조건 충족 시 자동 실행.

승인 흐름: 사용자 생체인증 + 권한 설명(탭 확인). L3 승급은 로그와 서명 필요.

스코프 제어: 트리거 반경(예: 집 반경 100m), 시간(예: 6:00-22:00) 제한.

예시: “집을 떠나면 도어 잠금 및 조명 끄기” 자동 실행.

롤백/안전: 실패 감지 시 원상 복구·알림(“스마트락 응답 없음 — 수동 확인 필요”).

감사: 자동화 실행 로그(입력변수 포함), 실패 사유 기록.

L4 — 민감처리 (Sensitive-Operate)

설명: 문서 전송(첨부 포함), 외부 API 쓰기(비금융), 타인 연관 데이터(허가된 가족) 접근 가능.

허용 권한: 파일 업로드/전송, 이메일 첨부 발송(사용자 승인 전제), 예약·티켓 생성 요청.

자동 수행: 제한적 자동화(사전 규정된 경우). 예: 계약 초안 전송은 기본적으로 ‘검토 후 발송’.

승인 흐름: 사용자 생체 + 신뢰인 1명(옵션) 승인 + 하드웨어 키 권장.

스코프 제어: 파일 확장자 필터(.pdf만 등), 수신자 화이트리스트.

예시: “세금 신고 서류를 세무사에게 전송” — 첨부 허용 시 자동 전송(사전 규칙).

안전: 첨부 파일은 클라이언트 사이드 스캔(PII 마스크) 옵션.

감사: 전송 전후 스냅샷(파일 해시) 및 서명 저장.

L5 — 금융·거래 (Transactional)

설명: 결제·구매·예약을 ‘대행’할 수 있는 수준. 금액 상한·가드레일 필수.

허용 권한: PG 호출(결제), 자동 구독 관리, 티켓 구매, 선결제 예약(호텔/항공 — 동의된 범위).

자동 수행: 사용자가 사전에 허용한 조건(예: 월 10만원 이하·카테고리: 생활용품)에서는 자동 구매 가능.

승인 흐름: 사용자 생체 + 하드웨어 키 OTP + 신뢰인(옵션) 서명. 초과 금액 시 수동 승인.

스코프 제어: 월/건당 상한, 허용 도메인/상점 화이트리스트.

예시: “예비 마스크 자동 구입 — 자동 결제 허용 월 5만원.”

롤백: 결제 실패나 이중청구 탐지 시 자동 환불 플로우(가능한 경우) + 알림.

감사: 결제 요청·승인·영수증(해시) 로그.

L6 — 사람대인 통신 (Representative)

설명: 에이전트가 외부 사람과 실무적 대화/협상(템플릿 기반) 대리 수행 가능.

허용 권한: 이메일/메시지(대화형) 전송, 템플릿 기반 대화 스크립트 실행, 약속 조율(상대방 자동 제안).

자동 수행: 정해진 템플릿·권한 내에서 자동 응답 가능(예: “회의 일정 잡기”).

승인 흐름: 사용자 + 신뢰인 1명 서명 + 대화 스크립트 사전 등록.

스코프 제어: 허용 문구·금지 문구 필터, 상대방 도메인 제한.

예시: “제안서 수신자에게 미팅 시간 3개 자동 제안”

안전: 민감 협상(계약 조건 변경 등)은 항상 사용자 확인 필요.

감사: 전송된 메시지 원문(해시)과 템플릿 버전 저장.

L7 — 권한 위임 (Proxy-Delegate)

설명: 특정 업무(예: 월간 운영 업무)의 전권 대행. 계약·서명 권한은 기본 불가(옵션 허용 시 하드웨어 서명 필요).

허용 권한: 업무 수행을 위한 전수집·실행(정해진 업무 내), 보고·결과물 제출.

자동 수행: 업무 루틴을 전권 실행(예: 월말 보고서 생성·발송).

승인 흐름: 사용자 서면 동의(전자서명) + 신뢰인 다수(2명 이상) + 하드웨어 키. 정기(예: 주 1회) 활동 보고 의무.

스코프 제어: 업무별 SOW(Statement of Work) 등록.

예시: “월간 경비 정산을 Hugin-Munin이 대행” — 최대 금액·수령인 제한 명시.

감사: 모든 송금·문서·커뮤니케이션 로그 및 결과물 저장.

L8 — 조직적 행동 (Organizational)

설명: 회사/팀 단위 계정 관리·조정, 타인 데이터(팀원) 연동·조작 가능. 높은 법적 책임.

허용 권한: 조직 캘린더 관리, 팀원 권한 조정, 조직 계정 결제(한도내).

자동 수행: 조직 규칙 기반 자동화(인사 알림·온보딩 플로우).

승인 흐름: 조직 관리자 + 법무/보안 담당자 승인 + 정기 감사.

스코프 제어: 조직 정책, 역할 기반 액세스 제어(RBAC).

예시: “신입 온보딩 체크리스트 자동 수행”

안전: 내부 감시·승인 워크플로 내장.

감사: 조직 수준의 보안 로그·사용자별 활동 리포트.

L9 — 법적/공적 행동 (Legal-Public)

설명: 법률 문서 준비·법적 프로세스 보조. 법적 자문 요구.

허용 권한: 법적 문서 초안 작성·제출 보조(실제 제출은 변호사/사용자 서명 필요). 수사·행정 대응용 문서 정리.

자동 수행: 제출 전 사용자/법무 검토 필요(자동 제출 불가 기본).

승인 흐름: 변호사/법무 담당자 + 사용자 + 하드웨어 키. 법적 견본·해석 기록 필수.

스코프 제어: 법률 관할·문서 타입 제한.

예시: “법적 서면 초안 생성 — 법무 검토 후 제출 권고”

감사: 문서 버전·해시·법무승인 로그.

L10 — 전권 대행 (Full Autonomy)

설명: 사용자가 허용 가능한 ‘거의 모든 행위’를 자동으로 대행. 최고 위험·최고 자율성.

허용 권한: 모든 외부 통신·결제·계약·대인 협상·데이터 액세스 포함(단, 법적·윤리적 제한은 여전히 적용).

자동 수행: 조건 충족 시 즉시 대행. 실패 시 자동 롤백 시나리오 필요.

승인 흐름: 엄격 — 사용자 전자서명 + 2명 이상의 신뢰인 서명 + H/W 키 + 법적 동의 문서 + 주기적(예: 7일) 재인증.

스코프 제어: 초과 금액·중요 계약은 별도 ‘휴먼 인 더 루프(HITL)’ 트리거.

예시: “월간 예산 승인 범위 내에서 정기적 공급 계약 갱신·결제”

안전: 전권 사용 시 별도 보험/법률 보호 문구 및 자동 사고 대응 라운드(알림/중지/롤백) 필요.

감사: 모든 행위의 불변증거(서명·해시·타임스탬프) 저장, 외부 감사 가능.

공통 설계 요소 (모든 등급에 적용)

스코프 세분화: 시간/위치/데이터 필드/액션 단위로 제한 가능.

임시권한(Token): 요청 시 발급되는 단기간(예: 10분/2시간/24시간) 토큰. 만료 즉시 폐기.

승급 제안만 가능: AI는 권한 ‘추천’만 할 수 있고 실제 승급은 사람 승인 필요.

시뮬레이션 리포트: 상위 등급 승급 전 예상 시나리오(3가지 케이스) 제공.

매회 로그 서명: 권한 발급·수정·사용 시 사용자 키로 서명된 로그 항목 생성.

주기적 재검토: L3 이상은 자동 재검토(30/90일) 알림.

Break-Glass(긴급 해제): 긴급 시 즉시 권한 상승 가능하지만, 사용 시 상세 사유·사후 감사·신뢰인 알림 필수.

학습(모델 업데이트) 제어: 설계 및 기능

사용자가 가장 중요하게 요구한 부분이라서 더 상세히 적음.

1) 기본 원칙

학습은 사용자 소유의 결정: 어떤 데이터가 학습에 쓰일지 사용자가 항목별로 허용/차단.

차단 모드(Pause Learning): 사용자가 활성화한 기간 동안(예: 1시간/하루/일주일/무기한) 해당 기기·계정에서 발생한 모든 활동은 학습 데이터로 수집/저장/모델 업데이트에서 제외.

항목별 학습 허용: 예: “일상 루틴은 학습 가능” / “음란물 시청 기록은 학습 차단” 등 데이터 카테고리별 토글.

임시 예외: 사용자가 특정 세션(예: 친구와의 상담)을 명시적으로 “학습 허용” 체크하면 예외 적용.

학습 로그: 어떤 데이터가 학습에 사용되었는지 투명 리포트 제공(날짜·데이터ID·모델버전).

2) UI: 학습 제어 패널 (구성)

전체 학습 토글: ON / PAUSE (기간 설정) / OFF

카테고리 목록: 일정·위치·음성·영상·브라우징·미디어(성인물 포함) ·메시지·통화 ·구매내역 등. 각 카테고리 옆에 ON/OFF/PAUSE 버튼.

세션 퀵 버튼: “지금부터 2시간 학습 차단” / “오늘 밤(22:00–07:00) 학습 차단”

세부 허용 예외: “특정 앱(예: 건강 앱)은 항상 학습 허용” 등 화이트리스트·블랙리스트.

학습 이력 리포트: 어떤 데이터가 언제 학습에 반영되었는지 모델 버전과 함께 제공.

3) 기술적 방안

데이터 라벨링 레이어: 수집 단계에서 ‘학습 허용 메타’ 부착. 차단 시 버킷킹(격리)되어 모델 파이프라인에서 제외.

On-device learning: 개인 임베딩과 간단한 업데이트는 기기 내에서 수행 — 네트워크 전송 불필요.

Differential Privacy (옵션): 중앙 서버로 업데이트 보낼 경우 선택적 차등개인정보 보호 적용.

학습 복구·롤백: 학습 버전 관리(모델 버전 + 데이터셋 버전). 차단 기간 이후에도 실수로 데이터가 반영됐을 경우 버전 롤백 가능.

4) 학습 관련 정책/알림

학습 차단 시 알림: 사용자가 차단 모드를 켜면 모든 관련 모듈(음성 인식·추천 엔진 등)에 실시간 표시.

자동 예외 경고: 일부 필수 데이터(예: 보안·사기 탐지용 메타데이터)는 학습 차단 외에도 익명화된 통계만 전송될 수 있음을 명시(사용자 선택 가능).

사용자 동의 기록: 학습 허용·차단의 모든 변경은 디지털 서명 로그로 저장.

임시 권한·차단 모드·Break-Glass 작동 (세부)

임시 권한(token) 포맷: {issuer, subject, scope, expires_at, conditions, signature} (서명된 JWT 유사)

차단 모드 예시 UX:

“학습 차단 ON — 2시간 (2025-12-01 14:00 ~ 16:00). 이 기간 동안 Hugin-Munin은 음성·영상·브라우징 데이터를 학습용으로 저장하지 않습니다.”

화면에 붉은 배너와 타이머 노출.

Break-Glass 프로세스: 긴급 권한 상승 버튼 → 인증(생체+PIN) → 사유 입력 → 권한 즉시 부여 → 즉시 신뢰인 알림(자동) → 사후 상세 감사 요구.

사후 심사: Break-Glass 사용 시 48시간 내 서면 사유 제출 & 신뢰인/관리자 심사.

실패·롤백 정책(전 등급 공통)

실패 감지: 자동 실행 실패 시 즉시 사용자 알림 + 실패 이유(에러코드) 제공.

롤백 우선순위: 금전·보안 관련 작업은 즉시 롤백 시도. 일반 자동화는 정의된 복구 시나리오 실행(예: 제어 실패 시 경고만).

사후 리포트: 실패 발생 시 24시간 내 상세 리포트(원인·영향·권장조치) 생성 및 서명 저장.

자동 중지 트리거: 비정상적 실패율(예: 5회 연속 실패) 발생 시 해당 자동화 일시 정지 및 관리자 알림.

신뢰인(Trustee)·역할 모델

신뢰인 유형: 가족, 법률대리인, 조직 관리자.

기능: 특정 등급(L4 이상) 승인·회수에 참여.

임명 절차: 사용자가 직접 등록 · 신원 확인(이메일+생체) · 공개키 등록.

탈퇴: 신뢰인 탈퇴 시 로그 기록 및 대체자 지정 권장.

구현 권고(핵심 기술 스택 요약)

암호화: AES-256-GCM (데이터), Ed25519 서명(로그), libsodium 권장.

키 저장: Secure Enclave / Android Keystore / 외부 HSM(YubiKey) 옵션.

DB: SQLCipher로 암호화된 SQLite.

On-device ML: TensorFlow Lite / ONNX Runtime.

API 토큰: 서명된 JWT 유사 포맷(단기간 토큰).

빌드 투명성: Reproducible builds + 공개 해시/서명.

운영·온보딩 권장 흐름 (사용자 초반 경험)

설치 시 L1(기본) 자동 부여.

‘권한 레벨 가이던스’ 튜토리얼 제공(각 등급 위험·예시).

초기 권한 요청은 단계별(권한 범위 축소 → 점진적 확대)로 유도.

주기적 권한 리포트(월간): 어떤 권한이 얼마나 사용됐는지, 비용/위험 이벤트 요약 제공.

MVP 우선순위 (빠르게 구현하면 큰 가치있는 기능)

권한 등급 시스템(L0~L3) + 권한 UI + 감사 로그(서명 포함).

차단 모드(학습 Pause) + 카테고리별 학습 토글.

임시권한 토큰 + Break-Glass 기본.

L4~L5 권한 승급 워크플로(생체 + 하드웨어 키 통합).

현실적 한계·법적 경고(명확히)

법적 요청(영장 등) 상황에서, 사용자가 서비스 제공자 호스팅을 이용하는 경우 메타데이터·암호문 일부가 요구될 수 있음. 완전 회피는 보장 불가.

키 분실 시 암호화 데이터 복구 불가 — 사용자가 복구 시드 안전 보관을 필수로 안내해야 함.

사용성·복잡도 트레이드오프: 높은 프라이버시·하드웨어 키는 편의성 저하를 초래. 사용자 교육과 UX 설계가 중요.

1. 설치 직후 (Day 1) 작동하는 기능
앱을 설치하자마자 즉시 작동하는 기능들은 다음과 같습니다. 학습이 필요 없습니다.

보안 비서: 권한 요청 시 생체 인증, 하드웨어 키 요구, 신뢰인 승인 등의 보안 절차.
기본 비서: 채팅, 음성 명령, 캘린더 일정 조회 ("내일 일정 알려줘" 등).
안전 장치: Break-Glass(긴급 모드), 백업, 학습 차단 스위치.
2. "학습(Learning)"의 현재 상태
현재 구현된 코드는 "학습을 위한 데이터 수집 및 통제" 단계까지 완성되어 있습니다.

지금 되는 것: 사용자님이 앱을 사용하며 발생하는 모든 로그(명령, 선택, 권한 승인 등)가 LearningControlManager의 통제하에 안전하게 로컬 DB에 쌓입니다. "학습 차단"을 켜면 이 기록조차 남지 않습니다.
아직 안 되는 것 (Next Step): 쌓인 데이터를 바탕으로 AI 모델이 스스로 변하는(Self-updating) 부분입니다. 현재 탑재된 ML 모델은 기본 지식만 가지고 있으며, 사용자님의 데이터로 재학습(Fine-tuning)하는 파이프라인은 아직 연결되지 않았습니다.
3. 언제부터 "기대하는 기능(개인화)"이 작동하나?
진정한 "나만의 비서"가 되기 위해서는 데이터가 쌓이는 시간과 모델 업데이트 로직이 필요합니다.

시나리오:
1주 차: 사용자님이 어떤 권한을 자주 승인하고 거절하는지, 어떤 시간에 방해받기 싫어하는지 데이터가 쌓입니다.
기능 추가 필요: 이 데이터를 읽어서 "아, 이 사용자는 평일 오전 9시에는 항상 알림을 끄는구나"라고 판단하는 **PersonalizationWorker (개인화 작업)**를 추가해야 합니다.
작동 시점: 위 기능을 추가한다면, 데이터가 약 50100건(약 12주 사용) 정도 쌓였을 때부터 눈에 띄게 패턴을 맞추기 시작할 것입니다.
